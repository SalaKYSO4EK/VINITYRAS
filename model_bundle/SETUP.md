# Локальное извлечение данных из научных PDF

Распакуйте весь model_bundle.zip в короткий локальный путь, например C:\PDFModel. В корне должны оказаться run_inference.py и manifest.json, рядом — runtime, models, config и submission_template. SHA-256 архива указан в соседнем model_bundle.sha256. В PowerShell его можно получить командой Get-FileHash -Algorithm SHA256.

## Запуск из любой рабочей папки

Сохраните запрос в UTF-8. Замените в нём путь на существующий PDF. Пример request.json:

~~~json
{
  "schema_version": 1,
  "job_id": "d143de096a7342848b3b9952fa2acb71",
  "criteria": "Извлеки PCE и Voc и укажи источники в PDF",
  "files": [{"name": "P006.pdf", "path": "C:/work/jobs/input/P006.pdf"}]
}
~~~

~~~powershell
& 'C:\PDFModel\runtime\python.exe' 'C:\PDFModel\run_inference.py' --request 'C:\work\jobs\request.json' --out 'C:\work\jobs\out'
~~~

Передайте каждый аргумент отдельным элементом при вызове из бэкенда. Используйте абсолютные пути. Выходной каталог каждого задания должен быть пустым или новым. Родительский каталог результата должен разрешать запись временной копии входных PDF и результатов. Сервисной учётной записи нужны чтение и запуск файлов пакета и право создавать временные файлы в models\criteria для llama.cpp. Входные PDF достаточно открыть на чтение. Критерии задания задаёт текст criteria. Исходные материалы кейса доступны в criteria\ как справочные файлы.

## На другом компьютере

Подходит Windows 10/11 x64 с Microsoft Visual C++ Redistributable v14 x64. Перенесите архив и файл контрольной суммы, проверьте сумму и распакуйте с сохранением каталогов. Если Windows сообщает об отсутствующей MSVCP140.dll, подготовьте официальный установщик vc_redist.x64.exe и согласуйте его установку с администратором. При наличии системной библиотеки первый запуск работает офлайн. Интерпретатор CPython 3.12.14 x64 находится в runtime\python.exe, библиотеки уже установлены и перечислены в requirements.lock.txt. Модели используют CPU. Практический ориентир — 8 ГБ ОЗУ, около 6 ГБ свободного диска на архив и распаковку плюс место для заданий. Задания, вызывающие модели, рекомендуется выполнять по одному.

## Протокол результата

Код 0 означает, что выгрузка готова. Последняя строка stdout — JSON с job_id, выбранным профилем и именами CSV. При фатальной ошибке скрипт возвращает ненулевой код и причину в stderr. На Windows дочерние процессы входят в Job Object вызова. При аварийной остановке родителя Windows завершает их. Для повтора прерванного задания используйте новый пустой каталог.

CSV находятся в корне --out. Кодировка UTF-8 без BOM, разделитель запятая, заголовки входят даже в пустую таблицу. publication_id — имя источника без последнего расширения. Передавайте в пределах задания уникальные имена PDF с учётом нечувствительности Windows к регистру. Значение name может отличаться от имени в path.

- Солнечный профиль сохраняет семь шаблонов кейса. Идентификаторы publication_id, result_id, device_id и measurement_id связывают записи. Ищите число, физическую страницу и цитату в results.csv, образец в devices.csv, условия в measurements.csv. Для подсветки ячейки используйте records.json, массив records, ключи source_file, source_page, sources.value, sources.header и context. Координаты рамок указаны в пунктах PDF от верхнего края. Обозначение источника для всей публикации находится также в documents[].file. В checks перечислены решения научных проверок. Файл check-submission.txt содержит результат однократного вызова штатного tools/check_submission.py по этим таблицам и входным PDF.
- Общий профиль использует имена групп и поля схемы, построенной Qwen, и базовую NuExtract для текстовых страниц. Имена CSV и число строк приведены в records.json. Каждая выгруженная строка содержит source_file, source_page с отсчётом от 1 и дословный source_fragment. При подтверждённой привязке доступны source_table, source_row, source_column, source_bbox, source_sample и source_conditions. Общий поиск по тексту не гарантирует научную корректность связи. Для произвольной темы новые правила вычислительной проверки автоматически не исполняются.
- report.json содержит массив строк warnings. Критерии после интерпретации и исходные ответы Qwen записываются в criteria-plan.json и qwen-raw.json. По вызванным этапам доступны ответы NuExtract и журнал извлечения свойств. Пустой результат может означать отсутствие читаемого текста или подходящей таблицы. Материалы и слои солнечного профиля извлекаются ограниченно. Для ряда проверок численные границы исходного кейса требуют уточнения.

Ревизия разборщика e67372288fd1 и хеши файлов указаны в manifest.json. Qwen интерпретирует запрос, табличный разборщик извлекает солнечные показатели по координатам. Базовая NuExtract используется для общего профиля и запрошенных названий, LoRA per-device — для свойств уже обнаруженных образцов. Строгая сверка разработки дала 28/28 для двух таблиц P083. В P078 найдены все 30 ячеек, у каждой пропущена комнатная температура из методики. Эти результаты относятся к конкретным таблицам.
