# NEXUS · Кибер-Гарден

NEXUS — локальный сайт для извлечения данных из научных статей. Пользователь загружает PDF или ZIP, задаёт критерии и получает таблицы, замечания проверки и ссылки на страницы публикаций. Сайт и обе модели работают на компьютере пользователя. Локальный комплект организаторов относится к тонкоплёночным солнечным элементам и хранится отдельно. Для других тем, в том числе RAG, есть общий режим извлечения по заданным полям.

## Запуск на Windows

**Дважды нажмите `start.cmd` в корне проекта.** При первом запуске откроется окно подготовки. Дождитесь браузера. Локальный адрес по умолчанию — **http://127.0.0.1:8087/**. Оставьте окно запуска открытым. Для остановки нажмите в нём **Ctrl+C**. Если браузер не открылся автоматически, скопируйте адрес из окна.

Целевая система — Windows 10/11 x64. В комплект входят CPU-версии моделей, Python 3.12 с библиотеками и собранный интерфейс. Для обычного запуска хватает Git с расширением LFS на этапе получения проекта. Python, Node.js и платный API отдельно устанавливать не требуется. Ориентир из документации модели — 8 ГБ оперативной памяти. Для полного клона, локального хранилища Git LFS, распаковки и первых заданий лучше иметь 10 ГБ свободного диска. Модели скачиваются при получении проекта, затем сайт работает офлайн.

### Перенос на другой ноутбук

1. Установите [Git for Windows](https://gitforwindows.org/) с компонентом Git LFS. Для отправки своих изменений войдите на GitHub под аккаунтом с правом записи.
2. Откройте PowerShell в папке, где хотите хранить проект. Желательно выбрать короткий путь на локальном диске.
3. Выполните команды. Клонирование включает около 2,36 ГБ весов и переносимого окружения, а также исходники и собранный сайт.

   ```powershell
   git lfs install
   git clone https://github.com/SalaKYSO4EK/VINITYRAS.git
   cd VINITYRAS
   .\start.cmd
   ```

4. В дальнейшем достаточно двойного щелчка по `start.cmd`. Если первое скачивание оборвалось, в папке клона выполните `git lfs pull` и снова откройте файл запуска. Для разработки на двух компьютерах используйте именно клон: в нём есть история, ветки и связь с GitHub.

### Первое задание

1. Откройте сайт и выберите научную статью в PDF. Если у вас есть учебный комплект, подойдёт `dev/D001.pdf`.
2. Введите критерий «Извлеки КПД (PCE) и напряжение Voc для каждого солнечного элемента и укажи источник». Вместо текста можно приложить PDF с критериями и указать страницы. Страницы PDF считаются с единицы.
3. Запустите обработку. Задания выполняются по очереди. Откройте итоговую таблицу, выберите число, проверьте страницу источника и скачайте ZIP с результатом.

## Состав проекта

| Файл или папка | Для чего служит |
|---|---|
| `start.cmd` | Главная кнопка запуска. Можно передать `-Port 8090` для другого порта и `-NoBrowser` для запуска без открытия вкладки. |
| `tools/start.ps1` | Проверяет наличие больших файлов, готовит переносимое окружение, запускает сервер и подключает собранный сайт. |
| `frontend/src/` | Исходники интерфейса на React и TypeScript. В `app/` находятся страницы загрузки и результатов, в `components/` — элементы интерфейса, в `lib/` — запросы к серверу и работа с таблицами. |
| `frontend/dist/` | Готовые HTML, JS и CSS. Они входят в Git, чтобы на другом ноутбуке сайт открылся без сборки. При изменении интерфейса обновите эту папку. |
| `frontend/package.json`, `package-lock.json`, `vite.config.ts`, `tsconfig.json` | Команды разработки, версии библиотек и настройки сборки. Все эти файлы находятся в `frontend/`. |
| `backend/server.py` | Запускает HTTP-сервер, раздаёт сайт и принимает запросы браузера. |
| `backend/uploads.py`, `jobs.py`, `pdf_criteria_runner.py` | Приём статей и архивов, очередь заданий и связь с моделью, чтение загруженного PDF с критериями. Все три файла находятся в `backend/`. |
| `backend/web/` | Упрощённая страница для отдельной проверки сервера. Главный запуск открывает NEXUS из `frontend/dist/`. |
| `model_bundle/run_inference.py` | Точка входа модели. Принимает запрос от сервера и записывает результат в каталог задания. |
| `model_bundle/article_analyzer/` | Код разбора текста и таблиц, поиска источников, проверки чисел и обработки произвольных полей. |
| `model_bundle/models/` | Базовая NuExtract-1.5-tiny, Qwen2.5-1.5B и программа llama.cpp для её запуска. Qwen разбирает критерии, NuExtract извлекает поля из текста. Для солнечных таблиц используется также положение ячеек на странице. |
| `model_bundle/artifacts/` | Обученная добавка к модели для извлечения свойств приборов и сведения о её подготовке. |
|  `model_bundle/config/`, `submission_template/`, `tools/` | Внутренние настройки комплекта модели, копия шаблона и утилиты обработки. Эти каталоги нужны самой модели. |
| `model_bundle/runtime-win64.zip`, `requirements.lock.txt`, `manifest.json` | Переносимый Python с установленными библиотеками, список версий и исходный перечень файлов пакета с контрольными суммами. Все три файла находятся в `model_bundle/`. |
| `dev/` и `dev_gold/` | 21 учебная статья и семь заполненных эталонных CSV. Здесь можно сравнивать результаты программы с разметкой организаторов. |
| `test/` | 90 PDF для итоговой проверки по солнечному направлению. |
| `submission_template/` | Семь пустых CSV и [правила заполнения](submission_template/README.md). |
| `tools/check_submission.py` | Проверка столбцов, связей между таблицами и привязки цитат к PDF. |
| `devices_work/` | Ранние эксперименты с таблицей приборов. Содержит скрипты извлечения и сравнения, текст страниц, сохранённые ответы модели и обученные параметры `.npz`. |
| `Демонстрация_devices/` | Пример выгрузки приборов, отчёт о сходстве с эталоном и подробные материалы сверки в `Проверка/`. |
| `Обработать статьи.cmd` | Отдельная консольная утилита прежнего эксперимента. После первого запуска сайта открывает выбор статей, запрашивает критерии и колонки. |
| `ВИНИТИ+ЮФУ.pdf`, `README_участникам.md` | Локальные презентация кейса и инструкция организаторов. |
| `.gitattributes`, `.gitignore` | Правила передачи крупных файлов через Git LFS и исключения локальных результатов, кешей и зависимостей. |

Папки `dev/`, `dev_gold/`, `test/`, `devices_work/`, `Демонстрация_devices/`, консольный эксперимент, исходная презентация и материалы организаторов относятся к рабочей копии команды. Они исключены из публичного репозитория. Для запуска NEXUS достаточно файлов из клона и вашего собственного PDF. Для воспроизведения оценки по эталону добавьте комплект организаторов локально.

### Какие таблицы получаются

В солнечном режиме `publications.csv` описывает статьи, `materials.csv` — материалы, `devices.csv` — приборы, `layers.csv` — слои, `measurements.csv` — условия измерений, `results.csv` — отдельные показатели, `issues.csv` — замечания. Таблицы связаны кодами внутри публикации. В общем режиме имена полей зависят от запроса. Пустая таблица допустима, если по критерию ничего не извлечено.

### Где искать свои результаты

При запуске из `start.cmd` сервер сохраняет задания в `backend/runs/local/<номер задания>/`. Там находятся исходные PDF, состояние задачи, журнал модели и каталог `output/`. В `output/records.json` хранятся привязки к источникам, в `report.json` — замечания. Результаты также доступны для скачивания из браузера. История заданий и загруженные пользователями статьи остаются на соответствующем ноутбуке. Для переноса конкретного результата скачайте его ZIP и передайте отдельно.

Консольная утилита создаёт папки `Результаты_…` в корне. Распакованный Python для сайта хранится в `%LOCALAPPDATA%\NexusPDF\<код папки>\runtime`. Его можно восстановить повторным запуском. Архив и обе основные модели версионируются в Git LFS.

## Работа вдвоём или с двух ноутбуков

Перед началом работы обновите основную ветку и создайте ветку своей задачи:

```powershell
git switch main
git pull --ff-only
git switch -c feature/my-change
```

После изменений выполните `git status`, добавьте нужные файлы через `git add`, сохраните их через `git commit -m "Описание изменения"` и отправьте ветку командой `git push -u origin HEAD`. На другом ноутбуке выполните `git fetch`, затем `git switch feature/my-change`. Для параллельных изменений используйте разные имена веток и объединяйте их через Pull Request в `main`.

### Если меняете интерфейс

Для разработки интерфейса установите Node.js 24 с npm. Из корня:

```powershell
cd frontend
npm ci
npm run typecheck
npm run build
cd ..
```

Сохраните вместе исходники и обновлённый `frontend/dist`. Для разработки с автоматическим обновлением оставьте основной сервер открытым и запустите Vite по инструкции в [frontend/README.md](frontend/README.md), с согласованными портами и разрешённым адресом интерфейса.

### Если меняете извлечение или сервер

Код модели находится в `model_bundle/`, а не внутри архива Python. После изменений перезапустите сайт. Чтобы проверить полученные семь CSV по исходным PDF, сначала запустите сайт хотя бы один раз, затем выполните из корня в PowerShell:

```powershell
$python = powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start.ps1 -RuntimePath
& $python .\tools\check_submission.py .\dev_gold .\dev
```

Вместо `dev_gold` и `dev` можно подставить свою папку с CSV и соответствующие PDF. Ошибки требуют исправления, предупреждения — сверки с публикацией. Подробные описания находятся в [справке сервера](backend/README.md), [контракте для команды модели](backend/Промпт_для_сборки_модели.md) и [описании исходного пакета модели](model_bundle/SETUP.md).

## Если запуск остановился

| Что видно | Что сделать |
|---|---|
| Ошибка Git LFS или файл модели размером около 130 байт | Выполните `git lfs install` и `git lfs pull` в клоне, проверьте вход в GitHub. |
| Порт занят | Закройте прежнее окно NEXUS либо запустите `.\start.cmd -Port 8090`. Адрес появится в окне запуска. |
| Windows сообщает об отсутствующей `MSVCP140.dll` | Установите [Microsoft Visual C++ Redistributable x64](https://aka.ms/vs/17/release/vc_redist.x64.exe) и повторите запуск. |
| Страница открылась, но обработка завершилась ошибкой | Откройте карточку задания и его `runner.log`. Для PDF с критериями проверьте, что нужный текст выделяется в PDF и диапазон страниц существует. |
