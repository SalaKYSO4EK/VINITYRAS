Собери готовый к запуску пакет текущей версии извлечения данных из научных PDF для нашего веб-интерфейса. Возьми актуальную рабочую сборку из `artifacts/final-12h` и сверься с `WORK_STATE.md`. Веб-сервер, загрузку файлов и очередь делает другой разработчик. Твоя часть — собрать существующий пайплайн и дать ему одну точку входа. Используй имеющиеся веса, адаптеры, конфигурации и критерии из задания. Свежий запуск обучения для этой интеграции не нужен.

**Команда, которую будет вызывать бэкенд**

```text
python run_inference.py --request <абсолютный путь к request.json> --out <абсолютный путь к пустому каталогу>
```

`request.json` будет в UTF-8. Пример структуры запроса:

```json
{
  "schema_version": 1,
  "job_id": "d143de096a7342848b3b9952fa2acb71",
  "criteria": "Извлеки PCE и Voc и укажи источники в PDF",
  "files": [{"name": "P006.pdf", "path": "C:/work/jobs/input/P006.pdf"}]
}
```

`criteria` приходит заново для каждого задания. `files` содержит уже распакованные PDF. Используй `name` как имя источника и сохраняй существующее правило получения `publication_id` из имени файла. Скрипт должен работать при запуске из другой папки. Разрешай пути к ресурсам относительно пакета или через документированную конфигурацию.

На успешном запуске положи CSV в корень `--out` и верни код `0`. Формат — UTF-8, разделитель запятая, строка заголовков обязательна. Для солнечного профиля из требований кейса выдай все семь файлов по существующему шаблону: `publications.csv`, `materials.csv`, `devices.csv`, `layers.csv`, `measurements.csv`, `results.csv`, `issues.csv`. Для остальных критериев выбирай таблицы по задаче и сохраняй ссылку на источник через `source_file` с точным именем PDF и `source_page` с физической страницей с 1. Сохраняй цитату, а для табличных значений — доступные обозначения таблицы, строки, столбца, образца и условий измерения. Используй актуальные проверки точности и связей. Не заполняй пробелы эталоном или догадками.

Если данных нет или часть PDF обработана с ограничениями, верни CSV с заголовками и добавь понятные пользователю причины в `issues.csv` или `report.json`. Допустимый `report.json` — объект UTF-8 с `warnings` как массивом строк. При невозможности выполнить задание верни ненулевой код и причину в `stderr`. Дочерние процессы, включая llama.cpp, должны завершаться в рамках вызова.
